# 2026.1106.3

This fork release retains the HTTP onboarding and unavailable-MCP UI fixes from
2026.1106.1 and 2026.1106.2.

- Allow non-loopback HTTP MCP and authorization origins only when
  `PAPERCLIP_MCP_ALLOW_INSECURE_HTTP=true` is explicitly configured.
- Keep HTTPS as the default, validate origin shape, and warn on startup when
  non-loopback HTTP is used.
- Preserve sign-in, consent, PKCE, callback/resource binding, company permissions,
  token validation, and revocation. Update deployment guidance for the opt-in.
- Cover configuration validation and HTTP discovery/authorization/code exchange
  with a loopback callback, including rejected invalid exchanges and origins.

This compatibility mode is for a custom local client on a trusted private
network. HTTP is unencrypted, and clients can independently require HTTPS.
The bundled Paperclip CLI continues to reject non-loopback HTTP. Enable
Assistant connections (MCP) in Settings → Experimental separately.
